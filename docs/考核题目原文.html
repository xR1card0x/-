一、考核说明

本次考核不考语法默写和算法题，允许全程使用 AI / Coding Agent，包括 ChatGPT、DeepSeek、Trae、Cursor、Codex、Qoder 等，也可以查询搜索引擎、GitHub 和相关技术资料。

不限制编程语言、框架和开发方式，也不强制要求后端或数据库。考核时间内如何安排需求分析、产品设计、开发、测试、Git 提交和最终完善，由考生自行决定。

AI 是本次考核允许并鼓励使用的开发工具，但不应替代考生自身的判断、取舍和验证。考生应对题目数据的理解、产品功能的合理性以及最终作品结果负责。机械照搬 AI 生成方案、未经验证直接采用生成内容、擅自补全题目未提供的事实，或单纯堆叠与实际场景无关的功能，均会影响综合评价。

本次考核重点关注作品的实用性、创新性、视觉与交互效果、产品思维和作品完整性，同时综合考察 AI / Coding Agent 使用、问题解决、迭代优化以及 Git / GitHub 基础工程习惯。

二、题目

大学生在日常学习和校园生活中，会持续接触比赛、项目招募、技术学习、科研、讲座、志愿服务以及各学院组织的校园活动。与此同时，学生个人也会自发发布约球、学习交流、项目组队、兴趣活动等信息。开放发布能够降低参与和组织门槛，但不同来源的信息在质量、完整性和可信度上可能存在差异，个别内容也可能夹杂推广、广告或与校园活动关联较弱的信息。

现在，你获得了下面一组模拟校园信息。请认真阅读全部材料，并结合真实校园使用场景完成产品设计。你的产品既应帮助同学发现、理解和参与合适的活动与机会，也应考虑学生自主发布活动、招募伙伴时的实际需求，以及多来源信息进入平台后可能产生的问题。

2.1 你的任务

利用 AI / Coding Agent，设计并完成一个面向在校学生、重点考虑新生使用体验的“校园活动与机会类小产品”。产品应能够帮助用户更有效地发现、理解、参与或发布题目所涉及的信息。

具体做成什么形式、重点解决什么问题、如何组织信息以及设计哪些功能，由你自行判断。不追求“大而全”，请优先做好最重要的使用场景，并在完成基础要求后，结合你对题目的理解，自主设计具有实际价值的功能或创新点。

创新不等于增加功能数量，也不等于使用更复杂的技术。如果一个功能能够明显减少用户判断成本、改善信息理解、提升使用效率或解决题目中没有直接写明但真实存在的问题，同样属于有价值的创新。

三、作品基础要求

1可实际运行

作品能够正常运行并实际操作，不能仅提交图片、PPT、设计稿或只有视觉效果而无法使用的静态页面。

2使用题目信息

必须实际使用题目提供的校园信息，合理呈现学校、学院及学生自主发布等不同来源的内容，产品功能应与题目场景保持明确关联。

3便于浏览定位

用户应能够较方便地浏览、定位或理解自己需要的信息，具体实现方式由你设计。

4至少 2 项核心功能

至少完成 2 项真正可用的核心功能，功能应产生实际结果，不应存在大量无效按钮或仅作展示的占位功能。

5支持自主发布

至少提供一种用户可以主动操作信息的方式，并支持学生自主发布活动或招募信息，使发布内容能够进入产品的正常使用流程。

6状态可保留

重要的用户操作结果在刷新或重新打开后应能够合理保留。

7至少 1 项创新功能

在上述基础要求之外，至少自主设计并实现 1 项与实际场景相关、具有明确用途的实用或创新功能。

8视觉与交互完整

产品应具备基本的视觉完整性和交互反馈，信息层级清楚、页面风格相对统一，并能够支持用户完成一个较完整的使用流程。

9Git / GitHub

使用 Git 进行版本管理，并将完整项目提交至 GitHub。

以上要求仅规定最低完成范围，不规定具体产品结构和实现答案。面对来源不同、质量不一的信息，如何兼顾开放参与、信息价值和平台使用秩序，由考生结合材料自行分析、取舍和设计。

五、GitHub 与项目交付要求

最终提交的 GitHub 仓库应保持可正常访问，并至少包含完整项目文件、3 次及以上有实际意义的 Commit 和 README。Commit 应能够基本体现项目开发、修改或迭代过程，不建议仅在考核结束前一次性上传全部内容。

README 应简要说明：产品名称、主要解决的问题、核心功能、运行方式、自主设计的实用或创新功能，以及你在题目材料或产品设计中主动发现并处理的一项关键问题。如果继续开发，还可以说明下一步最希望完善的内容。

不考复杂 Git 操作，也不要求必须使用命令行。Git / GitHub 主要用于考察基本项目管理习惯和最终交付规范。

六、考核过程说明

考核过程中，可能根据实际使用场景统一补充新的用户条件、信息变化或需求。考生应在现有作品基础上理解变化、作出判断并进行合理调整。具体如何调整，不提供固定答案。

允许继续借助 AI / Coding Agent 完成调整，但应自行验证调整后的功能是否合理、是否真正解决新的问题。考核重点之一，是观察考生能否在 AI 辅助下保持独立判断并持续完成有效迭代。

七、最终提交

考试结束前提交：GitHub 仓库链接 ＋ 可正常运行的最终作品。如项目存在特殊启动方式、环境要求或必要说明，请在 README 中写清楚。

八、评分主要关注

本次考核主要从以下方面进行综合评价：

1实用性

作品是否真正围绕学生的实际使用问题展开，核心功能是否有明确用途，能否减少信息获取、理解、参与或发布活动时的操作与判断成本。

2创新性

是否能够在基础要求之外发现值得解决的问题，并形成具有实际价值的功能或设计；不以功能数量和技术复杂度作为创新的唯一依据。

3视觉与交互效果

页面是否清晰易读、信息层级是否合理、整体风格是否协调，操作反馈和使用流程是否自然。

4产品思维

是否能够从目标用户、信息来源、信息状态、使用场景和优先级出发进行判断与取舍，并合理处理开放发布、信息质量与用户体验之间的关系，而不是机械完成题目或照搬 AI 建议。

5作品完整性

项目是否能够正常运行，核心流程是否闭环，功能是否真实可用，状态保存、测试、README 和 GitHub 提交是否完整规范。

AI / Coding Agent 的使用、问题解决与迭代、Git / GitHub 工程习惯均作为重要参考。技术复杂不等于得分更高，更关注理解、判断与完整交付。
