# 信息雷达站 · 数据库设计

当前版本为纯前端实现，用户操作结果（收藏、报名标记、发布、通知已读）持久化在浏览器 `localStorage` 中。本文档给出接入后端（如 SQLite / MySQL / PostgreSQL）时的完整关系模型设计，字段与前端数据模型一一对应，便于平滑迁移。

## 1. 概念模型（ER 概览）

```
users 1 ─── n activities        (users 发布 activities)
users 1 ─── n favorites         (收藏关系)
users 1 ─── n enrollments       (报名标记关系)
activities 1 ── n activity_updates (补充更新，如编号09/20)
activities 1 ── n reports       (举报/风险审核)
notifications n ─── 1 users     (通知，可由触发规则生成)
```

## 2. 表结构

### 2.1 activities 活动主表

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | VARCHAR(16) | PK | 编号，种子数据保留原始编号（01…26），用户发布用自增/雪花 |
| title | VARCHAR(60) | NOT NULL | 活动标题（≤50字，应用层校验） |
| category | VARCHAR(16) | NOT NULL | lecture / camp / contest / research / volunteer / teamup / student |
| source | VARCHAR(8) | NOT NULL | official（学校/学院）/ student（学生个人）/ risk（高风险） |
| org | VARCHAR(100) | | 来源单位，如"计算机学院""学生个人发布" |
| start_at | DATETIME | | 开始时间，NULL=未注明 |
| end_at | DATETIME | | 结束时间 |
| schedule_note | VARCHAR(255) | | 多场次/长期说明 |
| deadline | DATETIME | | 报名截止时间 |
| deadline_label | VARCHAR(30) | | 截止内容（报名截止/意向登记截止…） |
| signup | VARCHAR(255) | | 报名要求 |
| signup_mode | VARCHAR(255) | | 报名方式 |
| audiences | VARCHAR(64) | | 逗号分隔：all,freshman,sophomore,zero |
| effort | VARCHAR(100) | | 预计投入（小时/周） |
| capacity | VARCHAR(60) | | 名额（限30人/座位有限…） |
| fee_type | VARCHAR(8) | | free / paid / aa / unknown |
| fee_amount | DECIMAL(10,2) | | 收费金额（paid 时） |
| fee_note | VARCHAR(255) | | 费用备注 |
| loc_mode | VARCHAR(8) | | offline / online / both / unknown |
| loc_detail | VARCHAR(255) | | 具体地点 |
| contact | VARCHAR(120) | | 联系方式 |
| freshman | VARCHAR(8) | NOT NULL | good / caution / no |
| freshman_reason | VARCHAR(255) | | 评级理由 |
| origin_note | VARCHAR(150) | | 发布者来源说明（≤100字） |
| risk_signals | JSON/TEXT | | 风险特征数组（source=risk 时） |
| status_override | VARCHAR(8) | | 特殊状态标记（ended 等人工置位），否则由时间动态计算 |
| publisher_id | BIGINT | FK→users.id, NULL | 官方数据可为空 |
| view_count | INT DEFAULT 0 | | 浏览量 |
| created_at / updated_at | DATETIME | NOT NULL | |

索引：`idx_cat(category)`、`idx_deadline(deadline)`、`idx_source(source)`、`idx_start(start_at)`、全文索引（title + signup + loc_detail）用于搜索。

> 状态说明：open / closing / closed / full / ended / pending / updated 七态中，closing、closed、ended 由 `deadline`、`end_at` 与当前时间动态推导（即将截止阈值 72h）；pending（待确认）、updated（有更新）、full（已满）分别来自 `uncertain` 语义字段、`activity_updates` 存在性、部分方向满员标记，可物化为 `derived_status` 冗余列由定时任务刷新。

### 2.2 activity_updates 补充更新表

| 字段 | 类型 | 说明 |

| id | BIGINT PK | |

### 2.3 users 用户表

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| student_no | VARCHAR(20) UNIQUE | 学号（接入统一身份认证后启用） |
| nickname | VARCHAR(40) | 昵称 |
| contact | VARCHAR(120) | 常用联系方式 |
| role | VARCHAR(8) | student / admin |
| created_at | DATETIME | |

### 2.4 favorites 收藏表

`(user_id, activity_id)` 联合主键，`created_at` 记录收藏时间。

### 2.5 enrollments 报名标记表

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| user_id + activity_id | PK | |
| status | VARCHAR(8) | marked（已标记）/ attended（已参加）/ cancelled |
| created_at | DATETIME | |

### 2.6 notifications 通知表

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| user_id | FK | 接收人 |
| type | VARCHAR(12) | update / deadline / today / risk |
| title | VARCHAR(120) | |
| body | VARCHAR(255) | |
| activity_id | FK, NULL | 关联活动 |
| dedup_key | VARCHAR(80) UNIQUE | 幂等键，如 `dl-05-202609201200`，防止重复提醒 |
| is_read | TINYINT DEFAULT 0 | |
| created_at | DATETIME | |

通知生成规则（对应前端 `buildNotifications()`）：活动有新 update → 推送；收藏/已报名活动的 deadline 进入 48 小时窗口 → 提醒一次；已报名活动当日开始 → 提醒；关注的 risk 信息 → 风险提示。

### 2.7 reports 举报表

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT PK | |
| activity_id | FK | |
| reporter_id | FK | |
| reason | VARCHAR(16) | ads（广告推广）/ fraud（涉嫌诈骗）/ fake（虚假信息）/ other |
| detail | VARCHAR(255) | |
| status | VARCHAR(8) | pending / confirmed / dismissed |
| created_at | DATETIME | |

同一 activity 举报数达到阈值后，`source` 自动降级为 `risk` 并进入人工审核。

## 4. SQLite 建表示例（可直接运行）

```sql
CREATE TABLE activities (
  id            TEXT PRIMARY KEY,
  title         TEXT NOT NULL CHECK (length(title) <= 60),
  category      TEXT NOT NULL CHECK (category IN ('lecture','camp','contest','research','volunteer','teamup','student')),
  source        TEXT NOT NULL CHECK (source IN ('official','student','risk')),
  org           TEXT,
  start_at      TEXT,
  end_at        TEXT,
  schedule_note TEXT,
  deadline      TEXT,
  deadline_label TEXT,
  signup        TEXT,
  signup_mode   TEXT,
  audiences     TEXT DEFAULT '',
  effort        TEXT,
  capacity      TEXT,
  fee_type      TEXT DEFAULT 'unknown' CHECK (fee_type IN ('free','paid','aa','unknown')),
  fee_amount    REAL,
  fee_note      TEXT,
  loc_mode      TEXT DEFAULT 'unknown' CHECK (loc_mode IN ('offline','online','both','unknown')),
  loc_detail    TEXT,
  contact       TEXT,
  freshman      TEXT NOT NULL CHECK (freshman IN ('good','caution','no')),
  freshman_reason TEXT,
  origin_note   TEXT,
  risk_signals  TEXT DEFAULT '[]',
  publisher_id  INTEGER REFERENCES users(id),
  created_at    TEXT DEFAULT (datetime('now')),
  updated_at    TEXT DEFAULT (datetime('now'))
);
CREATE INDEX idx_act_cat      ON activities(category);
CREATE INDEX idx_act_deadline ON activities(deadline);
CREATE INDEX idx_act_source   ON activities(source);

CREATE TABLE activity_updates (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  activity_id  TEXT NOT NULL REFERENCES activities(id),
  ref_no       TEXT,
  title        TEXT NOT NULL,
  content      TEXT NOT NULL,
  published_at TEXT DEFAULT (datetime('now'))
);

CREATE TABLE favorites (
  user_id     INTEGER NOT NULL REFERENCES users(id),
  activity_id TEXT NOT NULL REFERENCES activities(id),
  created_at  TEXT DEFAULT (datetime('now')),
  PRIMARY KEY (user_id, activity_id)
);

CREATE TABLE enrollments (
  user_id     INTEGER NOT NULL REFERENCES users(id),
  activity_id TEXT NOT NULL REFERENCES activities(id),
  status      TEXT DEFAULT 'marked',
  created_at  TEXT DEFAULT (datetime('now')),
  PRIMARY KEY (user_id, activity_id)
);

CREATE TABLE notifications (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id     INTEGER NOT NULL REFERENCES users(id),
  type        TEXT NOT NULL,
  title       TEXT NOT NULL,
  body        TEXT,
  activity_id TEXT,
  dedup_key   TEXT UNIQUE,
  is_read     INTEGER DEFAULT 0,
  created_at  TEXT DEFAULT (datetime('now'))
);
```

## 5. 迁移路径

1. **第一阶段（当前）**：`js/data.js` 种子数据 + localStorage，单机可用；
2. **第二阶段**：以 `activities` 表导入种子数据（`SEED_ACTIVITIES` 数组即导入脚本的数据源），前端增加 API 适配层，读写从 localStorage 切换到 REST 接口；
3. **第三阶段**：启用 users 登录、notifications 服务端推送、reports 举报审核流，实现多设备同步与内容治理。
